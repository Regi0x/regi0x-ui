# Canonical UI component workflow

1. Read the local UI registry and closest stable components.
2. Prove that composition cannot solve the requirement before creating a new primitive.
3. New primitives start as Draft.
4. Implement all applicable states and semantic tokens.
5. Add live Dark/Light, EN/RU and long-copy/pseudo-localized examples plus narrow-container examples. Preview normal and reduced-motion behavior when the component moves.
6. Document purpose, anatomy, variants, sizes, interaction, keyboard, touch, accessibility, responsive behavior and motion.
7. Add an AI contract with USE WHEN / DO NOT / COMPOSE WITH / SOURCE OF TRUTH.
8. Update registry metadata.
9. Run UI checks. Do not promote maturity without explicit review.
