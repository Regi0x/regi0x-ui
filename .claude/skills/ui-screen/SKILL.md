# Reference screen workflow

1. Read registry, relevant patterns and product profile.
2. Compose existing primitives/patterns; do not create screen-local primitives.
3. Cover loading, empty, partial, error, permission-denied and success states where relevant.
4. Validate Dark/Light, EN/RU, pseudo/expanded copy when available, narrow/desktop, normal motion and reduced motion.
5. Mark screen Concept, Reference or Production; do not treat Concept as a production contract.
